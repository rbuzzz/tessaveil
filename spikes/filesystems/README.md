# Bounded filesystem replacement research

This disposable Windows PowerShell 7.4+ probe is not a vault implementation or a
release guarantee. It accepts only a caller-supplied, already existing **empty**
directory named `TessaveilReplaceProbe-<32 lowercase GUID digits>`, directly below
the system's ordinary shared Public directory. That directory must be on a fixed
local NTFS volume. There is no removable-device mode, format, mount, migration,
recursive deletion, or fallback to in-place writes.

Run the bounded harness from the repository root:

```powershell
pwsh -NoProfile -NonInteractive -File ./spikes/filesystems/Test-ReplaceProbe.ps1
```

The harness explicitly creates a new dedicated empty directory for each scenario,
starts a hidden child process, verifies the resulting bytes, and removes only
the exact synthetic files and empty directory it owns. Each child has a 20-second
limit. The complete run writes at most a few small synthetic images at a time.
The opt-in Python integration tests invoke the same harness:

```powershell
$env:TESSAVEIL_RUN_FILESYSTEM_PROBE = '1'
python -m unittest tests.repository.test_filesystem_report -v
```

For a single caller-prepared empty directory, pass its literal absolute path:

```powershell
pwsh -NoProfile -NonInteractive -File ./spikes/filesystems/ReplaceProbe.ps1 -Root $testRoot -FailurePhase AfterFlush
```

The dot-sourced interface is `Invoke-ReplaceProbe -Root <path> -FailurePhase
<phase>`. **Run it only in a disposable child process:** failure phases use
`Environment.Exit(86)`, bypassing stream disposal and `finally`. `None` is the
ordinary exit-0 control. Standalone runs leave their synthetic output for review;
a second run in the same nonempty directory is refused.

## Target safety

The strict path grammar rejects drive roots, relative paths, wildcards, traversal,
device/extended paths, UNC/network paths, arbitrary subdirectories and ordinary
cloud/user folders before writing. Explicit checks also reject the workspace,
current directory and user profile trees. The Public directory may not be
redirected. `QueryDosDeviceW` and `DriveInfo` reject mapped/substituted, removable
and non-NTFS drives. Each ancestor is opened without following reparse points,
resolved through `GetFinalPathNameByHandleW`, checked for reparse/offline/recall
attributes, and pinned without write/delete sharing for the operation.

`CfGetSyncRootInfoByPath` must return exactly
`HRESULT_FROM_WIN32(ERROR_CLOUD_FILE_NOT_UNDER_SYNC_ROOT)` (`0x80070186`);
registered cloud roots, unsupported APIs, unknown errors and uncertain status
fail closed. This is not a way to discover arbitrary third-party backup or legacy
sync software that does not register with Windows. The caller must not designate
a mirrored/synchronized Public location; such configurations are outside the
authorized test environment and receive no guarantee.

Files are created with `CreateNew`, never overwritten during setup. Every
replace/delete checks exact canonical parent, allowlisted basename, resolved
handle path, file kind, reparse attributes and a single hardlink. The test harness
separately creates one known directory junction and checks that the probe refuses
it; cleanup removes that exact link only, never its target recursively. No
personal paths or hardware identifiers are emitted in successful evidence.

The same-user/administrator adversarial mutation case is outside this research
scope. Directory pinning limits path substitution, but the final file check and
replacement are not one handle-relative transaction. This is not a hostile-OS
security boundary or a general-purpose safe file replacement library.

## Synthetic authenticated fixture

`fixtures/header-and-ciphertext.bin` is 4140 bytes, generated by `New-ProbeImage`:

| Offset / bytes | Meaning |
| --- | --- |
| 0 / 8 | ASCII magic `TVFS0001`, deliberately distinct from the product envelope |
| 8 / 1 | version 0 |
| 9 / 1 | KDF 0: public synthetic test key, no password/KDF |
| 10 / 1 | AEAD 1: AES-256-GCM, research only |
| 11 / 1 | flags 0 |
| 12 / 4 | little-endian ciphertext length 4096, exact bound |
| 16 / 12 | random GCM nonce |
| 28 / 4096 | ciphertext of random synthetic bytes |
| 4124 / 16 | GCM authentication tag |

The complete 28-byte clear technical header is AEAD associated data. No name,
table, dictionary, real phrase, seed, wallet or plaintext payload is serialized.
The key is SHA-256 of the public UTF-8 label
`Tessaveil filesystem probe public synthetic key v1`. It is deliberately public
and has no security value. Nonces and random payload bytes come from the OS CSPRNG;
plaintext exists only in transient memory and is cleared best effort. There is
no plaintext output. This does **not** change the proposed production
Argon2id/XChaCha20-Poly1305 format or its independent freeze gate.

`Test-ProbeImage` bounds length and structure, then actually decrypts and verifies
GCM authentication; SHA-256 identifies old/new bytes but does not substitute for
authentication. Negative tests mutate magic, identifiers, flags, length, nonce,
ciphertext and tag, plus truncation and trailing data. A public test key permits
forgery by anyone; the purpose here is detecting incomplete/corrupt disk images,
not resisting an attacker who knows the key.

The sequence is adjacent temporary create, write, `Flush(true)`, close/reopen and
authenticate, then `File.Replace` with no backup and metadata errors enabled.
PowerShell uses `NullString.Value` for the null backup argument; `$null` is
converted to an empty string by this overload and fails. There is no retry or
delete/rename fallback. See the [matrix](../../reports/spikes/filesystem-matrix.md)
and [ADR](../../docs/adr/0003-filesystem-replace.md) for the exact scope.
