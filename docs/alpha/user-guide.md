# Windows engineering alpha

**Unsigned engineering alpha. Synthetic data only. Never use real assets, a real
seed, order key, private key or wallet backup. No migration promise.** This alpha
uses `.tessaveil-alpha` schema 2, not the final `.tessaveil` format. Windows v1,
RC/stable release, final format/KDF freeze and static Qt redistribution remain
**NO-GO**. Security audit: not yet independently completed.

## Build and launch on the development host

Use the pinned external toolchain provisioned by the
[Windows spike](../../spikes/windows/qt-static/README.md): Rust 1.90.0 GNU,
LLVM-MinGW 20250709 / Clang 20.1.8, QtBase 6.8.3 static Widgets with network and
SQL disabled, CMake 3.31.8 and Ninja 1.12.1. Keep `$ToolchainRoot` an existing
external ASCII directory; do not copy tools or build output into the repository.
Run from the repository root, after assigning that variable:

```powershell
pwsh -NoProfile -File apps/tessaveil-windows/build.ps1 -ToolchainRoot $ToolchainRoot -Test
& "$ToolchainRoot/build/windows-alpha/Tessaveil.exe"
```

The helper builds the Rust archive with locked dependencies, statically links the
real core into Qt, and runs `alpha_ui_tests.exe` when `-Test` is given. It does not
download tools, publish an executable, contact a provider, sign or deploy. The
extra test executable is development tooling, not a second runtime requirement.
Use a plain, fixed local NTFS directory you own, outside cloud synchronization.
The core rejects unsupported save targets; development NTFS evidence is not an
atomic-save guarantee for removable media, other filesystems or power loss.

## Synthetic walkthrough

1. Read and acknowledge the launch warning. Type a new full path ending in
   `.tessaveil-alpha`, enter an invented master password of at least 15 normalized
   characters and choose **Create vault**. No password is retained after use.
2. Choose one of the three available profile/mode pairs: MyTonWallet, Tonhub or
   Tonkeeper classic, each with `ton-native-generated`. The matrix also shows
   unavailable records and their bounded reasons. Shared dictionaries do not
   imply shared mnemonic semantics. All selectable profiles use 24 rows here.
3. Choose 10 or 36 columns and **Add synthetic sheet**. A full decoy table is
   generated by the real OS-random core. Use the sheet selector or **Next sheet**.
   Scroll the table in both directions; row numbers and column headers remain.
   This app never constructs a complete phrase or an ordering key.
4. To exercise Spin safely, use an obviously invented token such as
   `synthetic-invalid-token`, one row number and two single symbols. Read the
   row-comparison warning and acknowledge it for each attempt. Spin replaces the
   whole row and clears the inputs; it does not report candidate validity,
   success, a target cell or a completion marker. ASCII `0–9` / `A–Z` is the
   symbol alphabet. No full phrase should ever be typed into this app.
5. **Verified by me** is a separate, explicit assertion following the displayed
   independent-recovery explanation. It is not cryptographic verification. Any
   Spin removes that assertion regardless of candidate validity.
6. Optionally enter an invented sheet password and choose **Set password**, then
   **Protect**. Unlock editing with that sheet password, or enter the master
   credential in the same protected input and choose **Use master**. A sheet
   password prevents accidental edits after opening the vault; it is not another
   cryptographic boundary after master-password or decrypted-payload compromise.
7. **Save** encrypts the current state and protects every sheet. Close the vault,
   then open the same file with its master password. **Lock** removes the usable
   session; **Unlock vault** authenticates the saved file again.

The default inactivity lock is five minutes; settings offer 1, 5, 15 or 30 minutes
for the current application run. Only in-app key, button, wheel and touch input
reset activity, not redraws or timer ticks. Windows lock, sleep and application
deactivation lock immediately. **Automatic locks discard unsaved changes** and
leave the last saved file intact; save before switching apps. Manual lock/close
offers Save, Discard or Cancel. A failed save keeps the current dirty session for
retry and does not knowingly replace the last authenticated file. Save failures
that leave an encrypted temporary image carry an explicit comparison-risk warning.

Wrong password and authenticated corruption share “The password is incorrect or
the vault is damaged.” Unsupported version and structural/KDF policy failures
remain separate safe messages. Authentication failure never opens an empty vault.

## Boundaries and handoff to Task 5

Multiple saved versions, copied backups or interrupted-save temporary images can
leak invariant words when compared after password disclosure. Regenerating decoys
does not remove that risk. This alpha has no backup/history, export, print,
screenshot, phrase import, clipboard, network, telemetry, update or provider
feature. Secret and table surfaces reject clipboard shortcuts, context menus and
drag/drop. OS screenshots, screen recording, hostile IMEs, paging and process
memory are outside this best-effort protection. Input buffers are cleared but
forensic erasure is not promised.

The UI is English with a dark theme. The sidebar scrolls at constrained heights;
Tab/Shift-Tab move between controls, arrows operate lists and the table, and focus
uses a turquoise outline. The app uses a native table model/delegate, not cell
widgets. Full localization, additional product flows and Narrator certification
remain future Windows-v1 work. These are development-host observations, not clean
Windows 10/11 or physical mobile evidence. The approved written focused-process
direction was used because no authorized Tessaveil Figma file/node was supplied.

**Do not publish/upload the static Qt binary yet.** Task 5 must first complete and
verify the LGPLv3 corresponding-source, notices, application object/relinking and
applicable installation-information bundle, including a successful relinking
exercise, or establish another lawful route. A single runtime EXE does not remove
those obligations. Signing, audit, clean Windows, physical mobile and removable
filesystem gates remain open. See [development observations](dev-host-ui-observation.md).
